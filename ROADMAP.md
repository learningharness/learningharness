# Direction

We want people to become more capable while working with AI, even when an agent is doing work beyond what they could do alone. Learning should be relevant to that work, fit the person's attention, and give them a chance to reason and practice.

This is a direction for discussion, not a delivery schedule. Open an issue to propose a small, testable step.

## Now: make the first session useful

- Reliable installation, restart guidance and permission review on supported hosts.
- A clear invitation and a first lesson worth opening.
- Better navigation, accessibility and understandable usage settings.
- Real evidence about relevance and learning value. Observe two fresh Mac users completing setup, including restart and hook approval, before expanding installation outreach. Record where they get stuck and whether the first lesson helps.

## Next: make it easier to contribute learning

- A documented path for adding learning tools and experiences with validated content and isolated rendering.
- Better feedback, review and continuity across work sessions.
- More useful controls for interests, pacing, model usage and memory.
- Clear evaluation scenarios and examples that contributors can reproduce without private projects.

## Explore: knowledge that grows with the learner

AutoKG-style discovery and a personal knowledge graph could connect the work a person encounters, the concepts behind it and the evidence of their understanding. Current local graph experiments are provisional, not an established taxonomy or a measure of mastery.

Explore reusing existing opportunity and teaching calls for bounded graph updates rather than processing an entire work stream again. Keep source provenance, uncertain relationships, learner evidence and assessed understanding distinct. Give people useful ways to inspect, correct, export and remove what the system remembers.

The test is whether this improves the next learning decision. A larger graph is not the goal by itself.

The AutoKG research branch starts with a [source review and comparison experiment](docs/research/AUTOKG.md). It does not change the current release or establish a learning benefit.

## Community, when there is a need

Start with useful issues and focused PRs. Add Discussions or a forum for work-in-progress ideas, learning experience design and feedback as participation grows. Establish a contribution gallery and clearer extension contracts when real examples justify them. We do not need a large community structure before people have something useful to contribute.

## Things we will preserve

The learning agent owns the learner's development, not supervision of the coding agent. Opening a panel does not authorize observation or paid work. Learner responses do not go into the main coding chat without explicit consent. Local memory, honest usage accounting and the ability to turn learning off are part of the product.
